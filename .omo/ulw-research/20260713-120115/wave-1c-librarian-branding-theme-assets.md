# Wave 1C — NixOS branding, colors, and local theme assets

Research date: 2026-07-13. Repository state audited: `e9f78180748f1feb428ffb20f9d932c5d9918a48`.

## Executive conclusion

The current NixOS brand authority is the [NixOS branding page](https://nixos.org/branding/), backed by the generated assets and guide in [`NixOS/branding`](https://github.com/NixOS/branding) (observed upstream HEAD `4faef6a7eb6094d0543d4047bd19551b3a2edf48`). The default official identity remains the blue NixOS logo. The current flat colors are `#4d6fb7` and `#77b6e1`; recommended general-purpose colored marks use gradients whose endpoints include those colors. Rainbow and trans marks are also sanctioned official variants, but the 2025 rainbow homepage deployment was a temporary Pride presentation, not a replacement of the default blue identity.

Neither local `nixos_logo_*.png` is current canonical artwork. `nixos_logo_1.png` uses the historical flat colors `#5277C3` and `#7EBAE4` and old geometry; `nixos_logo_2.png` is an unapproved cyan-violet derivative. More importantly, neither is active in the normal Fastfetch path: [`config.jsonc:3-7`](../../../modules/shared/config/fastfetch/config.jsonc) selects `snoopy-mugiwara.png`; the NixOS files are referenced only by the alternate `nixos-01.jsonc` and `nixos-02.jsonc` profiles. All local raster artwork, including Snoopy, lacks recorded source/license attribution in this repository.

The desktop is thematically coherent at a broad level (dark bases, blue/pink/violet accents), but not a single universal theme. GTK, Qt/Kvantum, KDE, Niri, Noctalia, terminals, editor, display manager, and macOS use multiple independent theme families and several declarations conflict or are stale. The most actionable defects are: missing `Sweet-cursors`; missing declarative Fira Sans; GTK's Adwaita-vs-Sweet split authority; runtime Noctalia state overriding declarative settings; competing wallpaper owners; unlicensed/unattributed local rasters; and copied GPL theme subsets that omit upstream license files.

## Current official logo and color findings

1. The current default palette is encoded in OKLCH at [`colors.toml:3-10`](https://github.com/NixOS/branding/blob/4faef6a7eb6094d0543d4047bd19551b3a2edf48/package-sets/top-level/nixos-branding/nixos-color-palette/colors.toml#L3-L10): dark `[0.55, 0.12, 264]`, light `[0.75, 0.09, 240]`. The generated flat SVG was downloaded and inspected; its fills are `#4d6fb7` and `#77b6e1`.
2. Current gradient stops are dark `#3e5993`, `#4564a5`, `#4d6fb7` and light `#6d9bbc`, `#72a9cf`, `#77b6e1`. The guide generally prefers gradient colored marks; black/white marks are flat, and flat colored versions are allowed for print/physical constraints. Do not reduce “official colors” to only two hex values when recreating the recommended gradient asset.
3. Rainbow and trans palettes are explicitly generated by the current repo at [`colors.toml:12-46`](https://github.com/NixOS/branding/blob/4faef6a7eb6094d0543d4047bd19551b3a2edf48/package-sets/top-level/nixos-branding/nixos-color-palette/colors.toml#L12-L46) and hosted in the official index. They are legitimate variants. The Discourse record explains only that the homepage's prolonged rainbow presentation was not a permanent change to the default identity.
4. The guide's primary/recommended composition is horizontal; vertical is secondary. It requires clearspace, high background contrast, and at least 24 px digital / 6 mm print height. It prohibits cropping, distortion, independent part scaling, rotation/mirroring, and similar-color backgrounds. These requirements should drive any wallpaper/terminal rendering, not visual approximation.
5. Current NixOS identity typography is Route 159; Jura is used in the guide/annotation system. Both are OFL-1.1. This repository's Sweet/Fira Sans desktop typography is a user theme and should not be described as official NixOS typography.
6. Creative branding assets are CC BY 4.0 and require credit, license link, and modification indication. The repository explicitly requests TASL attribution at [`README.md:137-180`](https://github.com/NixOS/branding/blob/4faef6a7eb6094d0543d4047bd19551b3a2edf48/README.md#L137-L180). Code is MIT; the creative assets are not.

## Prioritized local gaps

### High

1. **Provenance and license notices:** add an `ASSETS.md`/`LICENSES/` record with source URL, immutable revision or content hash, creator, license, and modifications for every raster and copied theme. The LightDM wallpaper has exact upstream identity and known restrictive terms; the active Snoopy artwork remains unresolved.
2. **Cursor package mismatch:** `Sweet-cursors` is configured but absent from the Sweet derivation and package list. This necessarily falls back or renders inconsistently.
3. **GTK split authority:** `modules/nixos/home-manager.nix:46-57` says Adwaita-dark while `modules/linux/home-manager.nix:509-557` and activation logic force Sweet-Dark. Standalone also declares adw-gtk3-dark before the shared force. Remove the losing declarations and ensure `config.gtk.theme.package` actually owns the requested GTK theme (the current NixOS declaration pairs a theme name with `adwaita-icon-theme`).
4. **Noctalia state drift:** v5 explicitly says runtime settings override `config.toml`. Audit or declaratively remove `~/.local/state/noctalia/settings.toml`; delete/archive the ignored v4 JSON and repair `docs/service-notes/noctalia-ddc-brightness.md:27`.

### Medium

5. **Fira Sans is requested but not installed declaratively:** add `pkgs.fira-sans` on Linux or change GTK/KDE/Waybar to a packaged family. Register the chosen terminal font in nix-darwin if physical-mac parity is required.
6. **Wallpaper ownership:** Niri starts `awww-daemon` (fallback `swww-daemon`) while Noctalia v5 enables wallpaper management. Select one owner and test cold login/reload behavior.
7. **Theme-family drift:** Sweet/Dr460nized/BeautyLine, pink Niri, Noctalia built-in M3, Catppuccin Ghostty/Zed, and unrelated wallpapers are compatible in mood, not a single palette. Define a small semantic token contract (background, foreground, blue, pink, violet, error, opacity) if exact consistency is intended.
8. **Nonportable absolute asset paths:** Waybar CSS references `/usr/share/icons/cachyos.svg`; Wlogout CSS references `/usr/share` and `/usr/local/share` icons. These are not Nix store paths and are likely stale. They remain linked in standalone configuration even if Noctalia currently replaces their UI.
9. **Packaged Malefor wallpaper is outside Noctalia's search root:** it is installed under `.local/share/wallpapers/Malefor`, whereas Noctalia watches `~/Pictures/Wallpapers`. Either link it into the selected library or remove unused installation.
10. **Alternate Fastfetch profile error:** both `nixos-01.jsonc` and `nixos-02.jsonc` reference `nixos_logo_2.png`; logo 1 is therefore orphaned even within alternates.

## Recommended asset policy

- To represent NixOS, consume an official generated file from `https://brand.nixos.org/logos/`, pin its SHA-256 (or pin `NixOS/branding` and build it), and preserve TASL attribution. Prefer SVG; only rasterize reproducibly for tools that cannot render SVG.
- Use the default blue horizontal/recommended gradient mark unless a small-square context genuinely calls for minimal geometry or accessibility requires black/white. Treat rainbow/trans as purpose-specific official variants, not the default identity.
- Do not redraw/recolor the mark from remembered hex values. A correct current render includes geometry, gradients, layout, clearspace, and contrast—not merely current endpoint colors.
- For personal art, retain only assets with a known creator and reuse permission. A filename, image-board page, or successful reverse-image search is not a license.
- For GPL theme derivations, copy the license and record the exact upstream commit and local modifications into the output, not only into Nix source expressions.

## Visual verification plan

1. **Freeze inputs:** evaluate all four targets and record exact store paths for Sweet, Dr460nized, BeautyLine, Candy, fonts, and the chosen official logo. Hash every raster. Capture the current Noctalia runtime settings file before resetting it.
2. **Brand asset checks:** render the pinned official SVG at 24, 32, 64, 128, and 512 px on light/dark/photo backgrounds. Compare geometry and pixel output with the downloaded official artifact; measure clearspace and contrast. Verify SVG metadata/license record and TASL notice.
3. **Linux cold-session matrix:** from a clean user state, capture GTK3, GTK4/libadwaita, Qt5, Qt6/Kvantum, KDE dialogs, file chooser, cursor, Niri border/shadow, Noctalia shell, Waybar/Wlogout (if retained), Kitty, Konsole, Ghostty, Zed, Fastfetch, lock/login screens. Test light/dark portals and application restarts.
4. **State/owner tests:** log in twice and reload Noctalia/Niri. Assert exactly one wallpaper daemon/owner, selected wallpaper persistence, no runtime settings silently overriding declared choices, and no cursor fallback warnings.
5. **Font verification:** use `fc-match 'Fira Sans'`, `fc-match 'FiraCode Nerd Font Mono'`, Kitty `+list-fonts`/debug output, and representative Latin/symbol/emoji/CJK screenshots. On macOS, verify the actual CoreText-resolved family on physical hardware.
6. **Icon completeness:** scan menus, tray, settings, file manager, MIME/file types, symbolic buttons, and fallback icons. Inspect inherited-theme resolution and report missing glyphs rather than relying on `index.theme` declarations.
7. **Display matrix:** capture at 1× and 2× scale, SDR and HDR where available, transparent/opaque terminal backgrounds, and multiple wallpaper luminances. Check text/icon contrast and border visibility, not only aesthetic resemblance.
8. **Automated regression:** add evaluations asserting one GTK theme, an installed cursor theme, installed requested fonts, valid Nix-store icon paths, Fastfetch source existence, and no ignored Noctalia v4 file. Keep screenshot baselines per platform; use structured visual verdicts for every visual change.
9. **Physical macOS verification:** confirm Kitty font/palette, emoji/symbol fallback, opacity behavior, and Fastfetch image rendering. GTK/Kvantum/Niri equivalence is out of scope; assess semantic colors and typography only.
